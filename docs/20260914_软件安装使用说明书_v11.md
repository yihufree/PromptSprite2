## 1. PromptSprite 是什么？能做什么？

**一句话版**：PromptSprite（提示精灵）是一个装在你自己电脑上的"AI 提示词图书馆"，帮你把几千条到处乱放的提示词整整齐齐地分类放好，想用的时候一搜一点就能复制走。

**再直白一点**：如果你平时用 AI 画画、写东西，会攒下很多"好用的指令文本"（比如某个画风的中文/英文提示词）。以前它们可能散落在记事本、Excel、聊天记录里，找起来很痛苦。PromptSprite 就是专门管这些东西的小工具——**所有数据都存在你自己的电脑里，默认不联网、不上传**。（V2.0.0 起新增了"网上资源结构化向导"里的**「从网址获取」**功能，只有你**主动去抓取某个网页/GitHub 文件时**才会联网；平时打开、使用、备份、导入导出都不会有任何网络行为，详见第 16 章。）

它能做的事，用大白话列出来：

| 序号 | 它能做什么 | 对你有啥用 |
|---|---|---|
| 1 | 像书架一样分层收纳提示词 | 项目类别 → 根目录 → 一级分类 → 二级分类 → 条目，再多也不乱 |
| 2 | 极速搜索 | 输入几个字，立刻从全部文字里找出相关条目 |
| 3 | 一键复制 | 复制"全部 / 只复制中文 / 只复制英文"，拷到 AI 对话框直接用 |
| 4 | 快速新建 | 鼠标"滑过去"就能锁定分类，连续录入几十条不打断 |
| 5 | 自动全量备份 | 每次打开软件自动把整个数据库存一份，出问题能退回 |
| 6 | 每日变更包 | 每天关软件时把当天的"新增/删除"自动打包，可拷到另一台电脑合并 |
| 7 | 回收站/删除历史 | 删错了？去回收站一键恢复，内容、收藏、位置都还在 |
| 8 | 多格式导入导出 | JSON / Excel / Markdown / HTML，从别处整理的数据能倒进来 |
| 9 | 老数据迁移 | 老版本的数据升级后自动迁移，不丢 |
| 10 | 数据比对 | 拿今天的数据和某一天的备份对比，看看到底多了啥、少了啥（只读，安全） |
| 11 | 标签系统（V2.0.0 新增） | 给条目打标签、跨分类聚合；标签页面支持标签云/列表查看、按标签筛选 |
| 12 | 条目图集（V2.0.0 新增） | 每条可以挂多张图（本地图 + 外链图），可排序、可把外链图"下载到本地" |
| 13 | 自定义字段与类型（V2.0.0 新增） | 自己加字段、改字段类型（文本/数字/日期/是·否/链接/列表框/标签/附件/短音频/图像等） |
| 14 | 网上资源结构化向导（V2.0.0 新增） | 粘贴文本 / 本地文件 / **从网址抓取**，自动整理成"四级分类 + 字段"的条目，先存文件再导入 |
| 15 | 智能标签与预置标签（V2.1.0 新增） | 出厂标签词表共 **135 个标签**；内置库已给全部条目**预置好标签**（2555 条 → 622 个标签 / 6579 条关联），打开就能按标签浏览、筛选 |
| 16 | 批量智能自动打标（V2.1.0 新增） | 一键给"**仅无标签的条目**"或"全部条目"批量打标签；**必须先预演**、**执行前自动备份**、执行后可**精确撤销** |
| 17 | 词表管理（V2.1.0 新增） | 标签词表可导出 / 导入 / 恢复出厂；**要新增一个大类（如"学术"），自己改 JSON 再导入即可，无需改代码** |
| 18 | 热点词表（V2.1.0 新增） | 维护一份"热点词"清单（手动逐条添加 / 粘贴文本导入 / 从来源网址抓取），供自动打标参考使用 |

**软件自带内容（内置精简模板）**：4 个项目类别、10 个根目录、约 2555 条提示词示例（主要集中在"网上资源收集"下），打开就能看、能抄、能改。**V2.1.0 起，内置库还额外附带"预置标签"：622 个标签、6579 条标签关联**，因此新装用户打开标签页面就能直接按标签浏览（详见第 20 章）。

## 3. 两种运行方式：打包 EXE 与从源码运行

### 方式一：使用打包好的 EXE（推荐给所有普通用户）

打包好的程序是一个单文件，命名规则是：

```
PromptSprite_<打包日期YYMMDD>_V<版本号>.EXE
```

例如：V2.0.0 的包是类似 `PromptSprite_260914_V2.0.0.exe` 的名字（`260914` = 打包日期 2026-09-14）。
**V2.1.0 的包名为 `PromptSprite_260914_V2.1.0.exe`**，体积 **23.40 MB**（上一版 V2.0.0 为 23.19 MB），打包时间 2026-09-14 13:24:22；校验值（SHA256）为 `51C7E5487EB2EE75C3BAA93D63BF8C93D05A206DA136FC43CA24F2138FBC84C5`（详见第 22 章）。

安装步骤（其实不用"安装"，解压即用）：

1. 把下载到的 EXE 文件放到一个**英文路径**的文件夹里，例如 `D:\PromptSprite\`（路径里有中文有时会被杀毒软件或系统误伤）。
2. 双击这个 EXE 启动。第一次启动需要几秒到几十秒（要自动准备数据），**期间不要关窗口**。
3. 程序会在 EXE 所在的文件夹里自动创建一个 `data` 文件夹（你的全部数据都在里面，见第 3.3 节）。

> 换电脑/换文件夹：**请把整个文件夹（包括 `data` 文件夹）一起复制**，而不是只复制 EXE。只拷 EXE 不拷 `data`，新电脑上是空白模板数据。

### 方式二：从源码运行（开发者 / 爱折腾的用户）

软件是 Python 写的。想从源码跑，需要自己准备环境：

1. 安装 Python（3.10 及以上，推荐 3.12）。
2. 把仓库源码下载/克隆到本地。
3. 在项目根目录打开命令行（PowerShell），安装依赖：
   ```
   pip install -r requirements.txt
   ```
4. 启动软件（二选一，效果一样）：
   ```
   python -m app.main
   ```
   或
   ```
   python run.py
   ```
5. 程序启动后，数据文件夹在**项目根目录**下的 `data\`（和 `app\` 平级）。

> 小提示：源码方式运行时，如果缺了第三方库，软件会尝试自动 `pip install` 补齐；自动安装失败时按提示手动执行上面第 3 步即可。

### 3.3 `data` 数据文件夹里到底有什么？（重要，先看懂再动手）

不管哪种运行方式，你的全部家当都在 `data` 文件夹里。它的结构长这样：

```
data\
├── prompts.db                    ← ★主数据库★（你的全部提示词、分类都在这一个文件里）
├── images\                       ← 条目关联的图片（有配图的条目才出现这个文件夹）
└── backup\                       ← 备份目录
    ├── prompts_2026-09-09_08-30-15_123456.db   ← 自动全量备份（每次启动软件生成一份）
    ├── prompts_2026-09-08_23-48-52_494227.db   ← 更早的自动备份
    ├── snapshot_施工前_20260829.db             ← 手动快照（你自己复制的备份，永远不被自动清理）
    ├── prompts_preimport_2026-09-09_09-00-01.db ← 导入前自动快照（导入变更包前自动生成）
    └── incremental\               ← 每日变更包目录
        └── 变更包_DESKTOP-hahaha_2026-09-09_add_1_del_1.json   ← 当日变更包（第 8 章细讲）
```

逐项说明：

| 文件/文件夹 | 是什么 | 能不能删 |
|---|---|---|
| `prompts.db` | 主数据库，**一个文件=全部数据** | 千万别删！删了数据就没了（除非有备份） |
| `data\backup\prompts_日期时间.db` | 每次启动软件时自动生成的"整库快照" | 软件自己按规则清理（默认留最近 30 份），你一般不用管 |
| `data\backup\snapshot_xxx.db`、`*_施工前_*.db` 等 | 手动快照（人肉复制出来的保险） | 软件**永远不**自动删，你自己决定留不留 |
| `data\backup\prompts_preimport_*.db` | 导入变更包前自动生成的安全快照 | 软件**永远不**自动删，可手动清理 |
| `data\backup\incremental\变更包_*.json` | 每天关软件自动生成的"当天变更记录" | 软件默认只保留最近 30 天（设置里可改天数） |

> **想手动做"手动快照"？**（比如大扫除前想留个保险）做法：先**关闭软件**，把 `data\prompts.db` 复制一份到 `data\backup\` 里，改个普通名字，比如 `snapshot_大扫除前_20260909.db`。只要不叫 `prompts_日期_时间.db` 这种标准名，软件永远不会自动删它。
> **怎样手动恢复备份？**：关闭软件 → 用备份的 `.db` 文件**覆盖** `data\prompts.db`（先把原来的 prompts.db 改名留底更稳妥）→ 重新打开软件。

## 4. 第一次启动会发生什么

第一次双击 EXE（或第一次从源码运行）时，软件会依次自动做这几件事，**请耐心等它做完，别中途关窗口**：

1. **自动建库/自动准备数据**：在 `data` 文件夹里生成主数据库 `prompts.db`。
   - 用 EXE 运行时：自动从程序内部复制一份"内置完整模板库"（含 4 个项目类别、10 个根目录、约 2555 条提示词），开箱即用。**V2.1.0 起，这份内置库已预置标签**（622 个标签 / 6579 条标签关联），所以第一次打开软件的"标签页面"就能看到大量现成标签，无需自己一个个打（详见第 20.1 节）。
   - 从源码运行时：自动建表 + 预置根目录，再自动导入内置手册（会弹出进度条窗口，导完自动消失）。
2. **版本升级时（可选）**：如果检测到内置手册有新版本，会自动做一次"非破坏性合并导入"——只增加新内容，**不会清空你已经存的数据**。
3. **老版本数据迁移（自动弹出）**：如果你的 `data` 里有老版本留下的数据、且根目录还没有归入"项目类别"，会自动弹出"数据迁移向导"帮你整理（详见第 11 章）。如果没有老数据，就不会弹。
4. **设置电脑代号（重要但不急）**：首次使用时，软件自动把"电脑代号"设为本机主机名（例如 `DESKTOP-hahaha`），并记在设置里。
   - 电脑代号干什么用？——给"每日变更包"文件命名用。这样从两台电脑拷来的变更包文件不会重名，能分清"这是哪台电脑产生的"。
   - 在哪里改？——右上角 **⚙ 设置 → 电脑代号**，可随时改成你自己好认的名字（如 `办公室电脑`），改完点"确定"。
5. **注册全局热键与系统托盘**：注册成功后，在任何地方按 `Ctrl+Shift+P` 都能把 PromptSprite 唤到前台并把光标放到搜索框；按 `ESC` 可把窗口藏到托盘。注册失败不影响使用（见 FAQ 12.8）。
6. 底部状态栏会显示统计，例如：`总提示词数 2555｜项目类别 4｜根目录 10｜一级目录 …｜二级目录 …`。

### 5.2 左侧多级书架（项目类别 → 根目录 → 一级 → 二级 → 条目）

数据像书一样分层存放，共五级（中间三级分类书架 + 条目）：

```
项目类别（最高层，如：网上资源收集）
 └── 根目录（如：海外AI绘画案例库）
      └── 一级分类（如：Portrait & People）
           └── 二级分类（如：Street & Urban）
                └── 条目（一条提示词，如：雨夜霓虹街景风格）
```

- **项目类别**（第一列）：给大方向分堆，如"日常学习记录 / 网上资源收集 / 个人梳理资源 / 本人创作作品 / 个人经验总结"。软件内置数据主要在"网上资源收集"里。
- **根目录**（第二列）：项目类别下面的大类，例如"视频 / 图像 / 海外AI绘画案例库 / GPT Image 提示词库"。
- **一级分类 / 二级分类**（第三、四列）：继续往下细分。
- **条目**（第五列）：真正的一条条提示词。每条有一个名称和一串内容字段（第 19 章讲 ①~⑩）。
- 名称太长显示不全？——每列宽度有限，**鼠标悬停到名字上就会弹出完整名称提示**。
- 逐级操作方式：**鼠标单击或悬停**（约 0.2 秒）任意"项目类别/根目录/分类"，右边一列就会自动刷新出它的下级；点一条条目，右侧详情区就显示它的内容。
- 底部状态栏会随着你鼠标悬停的位置，实时显示这一层有多少条提示词。

### 5.3 右侧详情区（看一条、改一条都在这）

选中一条条目后，右边详情区从上到下是：

1. **命令按钮行**（V1.8.0 起顺序与宽度调整）：**☆ 收藏 → ➜ 移动到 → ↔ 关联到 → ⧉ 复制到**（靠左排列，名称已去掉末尾省略号），最右侧是 **✏️ 编辑 / 👁 浏览** 切换开关（见 5.5 节）。
2. **提示词复制行**：📋 复制全部 / 复制中文 / 复制英文（绿色大按钮"💾 保存"、"重置"在这行右侧）。
3. **位置面包屑**（浅色横条）：告诉你这条现在在哪，例如 `🧭 网上资源收集 › 海外AI绘画案例库 › Portrait & People › Street & Urban`。如果一条内容同时挂在多个位置（见 6.6 节"关联到"），这里会列出所有位置，每个关联位置旁边有个"×"可以单独解除。
4. **字段内容区**：内置 10 个字段（① 条目名称 + ②~⑩ 内容），每个字段是带彩色边框的独立小卡片，方便区分（第 19 章有字段对照表）。②~⑦ **整组默认折叠成 1 行标题**，点"展开"（或顶部"⏵ 显示全部字段"）才全部展开；⑧⑨ 两个提示词大字段默认折叠成约 6 行高，点"展开"就能看全文。**V2.0.0 起**：⑦"代表高清配图"升级为"**封面 + 图集**"（见第 14 章）；这里还会出现 **🏷 标签** 区块（见第 13 章）；如果你在"字段管理"里加了自定义字段，它们也会作为独立卡片出现在字段区（见第 15 章）。
5. **底部常驻栏**（V1.8.0 起靠右停靠，V1.9.0/V2.0.0 增强）：最左是几个小图标按钮 —— **🗂**（一键全部隐藏/全部显示各分类区域，与工具栏"目录隐藏/目录显示"等效；**V1.9.0 起按钮会变色**：目录打开＝**绿色**、目录关闭＝**黄色**，鼠标悬停有提示"打开/关闭四级目录"）、**💬**（**V1.9.0 新增**：一键打开/关闭"条目名称一览"与"详情区字段提示"两类浮动提示，**蓝色＝开、灰色＝关**，悬停提示"打开/关闭浮动提示窗口"，见 5.7 节）与 **🏷（V2.0.0 新增）**（打开/关闭**标签页面**，与"四级目录"互斥，见第 13 章）；右侧依次 **🕒 新增历史 ｜ ♻ 删除历史/回收站 ｜ 🗑 删除当前条目**（第 6、7 章细讲）。

> 不同根目录下，右侧字段的多少可能不一样：软件默认"自动"策略——**仅在"视频""图像"两个根目录下完整显示 ②~⑦，其余根目录只显示 ② 介绍**。（V1.9.0 及更早版本里这个"自动"设置其实未真正生效，V2.0.0 已修好。）想临时全部显示？→ 点详情区头部"⏵ 显示全部字段"（只对当前这次查看生效）；想长期全部显示？→ ⚙ 设置 → 详情字段显示 → 改成"全部显示"。

### 5.4 目录隐藏 / 目录显示（V1.8.0 新功能）

左边四列分类（项目类别 / 根目录 / 一级分类 / 二级分类）可以**随你的习惯收起来**，把空间让给"条目 + 详情"：

1. 点工具栏 **🗂 目录隐藏** → 弹出对话框，勾选要隐藏的列（**勾后面的列会自动勾上它前面的列**，保证隐藏的是从"项目类别"起连续的一段）；对话框右侧还有"快捷选项"：**全部隐藏 / 全部显示**，可一键全收或全放。
2. 确认后按钮变成 **🗂 目录显示**；再点开对话框勾选要恢复的列（**勾前面的列会自动带上它后面的列**），确认即恢复。
3. 底部常驻栏最左的小图标 **🗂** 是"一键开关"：点一下全部隐藏，再点一下全部显示。
4. **窗口最小宽度会跟着变**：四列全显示时窗口不能小于约 **1496** 像素宽（V1.9.0 及更早为约 1420，V2.0.0 因新增 🏷 标签页面按钮等略增）；隐藏得越多，可缩得越窄（四列全隐藏时最小约 **1104**，此时只剩"条目 + 详情"两栏，适合把详情区看窄一点或并排摆放）。

> 隐藏只是"不显示"，不影响数据；点它只是界面切换，恢复后分类位置不变。

### 5.5 编辑 / 浏览 切换（V1.8.0 新功能）

详情区右上角的 **✏️ 编辑 / 👁 浏览** 开关用来**防止误改**：

- **✏️ 编辑**（默认）：和以前一样，可以改字段、保存、删除、移动等。
- **👁 浏览**：详情内容变成"只读"，鼠标仍可**选中并 Ctrl+C 复制**；同时"保存 / 重置 / 删除当前条目 / 移动到 / 关联到 / 复制到"会置灰不可点。适合"只想看和抄"的时候。
- 只有"有当前条目"时开关才可用；进入"＋新增条目"或没有选中条目时会自动回到编辑态并置灰。

### 5.6 条目列太长看不全？悬停看"条目名称一览"（V1.8.0 增强，V1.9.0 调整字号与高度）

条目列宽度有限，同屏看不全时：

- 把鼠标**停在条目区约 0.5 秒**，会在条目列左侧浮出 **📋 条目名称一览（共 N 条）** 小窗，一次看全当前分类下所有条目名。
- **V1.9.0 调整**：浮层里的文字**字号与条目名称完全一致**（卡片视图 13、列表视图 12），窗口**最小高度固定为可显示 25 行**——条目不足 25 条时下方留空行，多于 25 条时用右侧滚动条查看。看得更清楚、也不用反复上下找。
- 浮层里的列表可以滚动：**在条目区滚动滚轮时浮层会跟着同步滚动**；也可以**把鼠标移进浮层**（浮层不会消失）直接拖它的滚动条或滚轮浏览。
- 鼠标移出条目区与浮层后，浮窗自动关闭；切换分类/搜索时也会立即关闭，不会残留旧数据。

### 5.7 详情区字段"浮动提示窗口"（V1.9.0 新功能，重点）

详情区里的字段（② 介绍、⑧ 中文提示词……）文本框都不高，超长内容常常看不全。**V1.9.0 起**，把鼠标**停在某个字段的文本框上约 0.35 秒**，就会在**详情区左侧**浮出一个"📄 字段名 · 完整内容"窗口，把整段内容一次看完：

1. **位置固定、不挡正文**：浮窗始终贴在**详情区左侧**（条目/分类列上方），**不会盖住右侧详情内容**；顶部与被悬停的字段对齐，方便上下逐行对照。
2. **宽度自动适应**：详情区左侧空间充足时较宽（最多约 610 像素）；若点了 **🗂 目录隐藏**把左侧分类列收起来，左侧只剩"条目"一列，浮窗会**自动变窄**——无论何时都不会压住详情正文。
3. **内容多可滚动**：窗口右侧有滚动条；把鼠标移进浮窗（**浮窗不会消失**）即可用滚轮或拖动滚动条查看；窗口高度最少显示 **18 行**、最多 30 行（超出滚动）。
4. **滚动同步**：浮窗打开时，用鼠标在**该字段文本框里滚动**，浮窗内容会**同步滚动到相同位置**。
5. **光标行加深**：鼠标在文本框里移到哪一行，浮窗内**同一行会以浅蓝底色加深**，一眼就能对上位置。
6. **文字更大**：浮窗字号为 **14pt**，比详情文本框里的字更大，看着不累眼。
7. **不再闪烁**：光标可以自由地在文本框与浮窗之间移动，不会出现"提示窗闪一下就没、鼠标和窗口一直抖"的问题（这是 V1.9.0 修掉的老毛病）。
8. **不想用时一键关掉**：点详情区左下角的 **💬** 按钮（蓝色＝开、灰色＝关）可**同时关闭**"条目名称一览"与"详情区字段提示"两类浮动提示；再点一次即恢复。注意：各按钮、分类列长名称的悬停提示**不受**这个开关影响，仍可正常查看。

> 小贴士：浮窗显示的是"打开它那一刻"的内容。如果你在浮窗开着时改了字段文字，把鼠标移开再重新悬停一次即可刷新。

## 6. 基本操作

### 6.1 新增一条提示词（两种入口）

**入口 A：主界面就地新增（推荐，最直观）**

1. 在左侧书架逐级选中一个分类（一级或二级分类都可以——软件允许"任一分级分类直接持有本级条目"；也可以先点 📂 未分类 再新增）。
2. 点条目区顶部的绿色按钮"＋ 新增条目"。
3. 右侧详情区变成"新增表单"：在 **① 条目名称（风格名称）** 里输入名称（必填），然后填②~⑩（可只填提示词：⑧中文版、⑨英文版，其余留空也完全没问题）。
   - ③~⑦ 这些补充信息在新增表单里默认折叠成一组，需要时点"展开"再逐项填。
4. 点"💾 保存"。保存后自动回到列表，新条目出现在当前分类里。

**入口 B：✚ 快速新建（连续录几十条时最爽）**

1. 点顶部工具栏"✚ 快速新建"，弹出快速新建窗口。
2. 窗口左边有四列（项目类别 → 根目录 → 一级分类 → 二级分类），**鼠标悬停**即可逐列展开，**不用点击**：滑到某个项目 → 根目录自动刷出；滑到根目录 → 一级分类刷出；再滑到某个分类 → 如果它没有子分类就直接"锁定"它（窗口顶部会显示"已锁定分类：xxx"）。
   - 想存到没有分类的地方？窗口角落有"📂 归入未分类"按钮。
3. 锁定后，光标自动跳进"① 风格名称"输入框，直接输入回车/保存即可入库；表单自动清空，**可以不停手地连续录入**。
4. 录完关闭窗口，主界面自动刷新。

> 锁定状态（🔒）下不能新增；未选中任何分类时主界面的"新增"按钮是灰的，选好位置就亮了。

### 6.2 查看与编辑

- **查看**：左侧点一条条目，右侧详情区即显示。⑧⑨ 提示词内容超出文本框时自动有滚动条；点"展开"查看完整全文（中文/英文提示词不设长度上限）。
- **编辑**：直接在右侧字段里改文字 → 点"💾 保存"。
- **重要防手滑**：如果你在编辑中途去点其它条目，软件会弹窗问：**保存 / 放弃 / 取消**——选"取消"可以回到刚才那条继续改。
- 右侧有个"重置"按钮：把本字段/本次改动还原。
- **记住**：一个条目如果同时"关联"在多个位置（6.6 节），改任何一处保存后，**所有位置的同一内容会一起变**（因为它们本来就是同一条）。

### 6.3 收藏与常用

- 选中条目 → 点详情区"☆ 收藏"（变"★"）。再点一次取消收藏。
- 点顶部"⭐ 常用"，就能看到所有收藏过的条目。收藏状态在回收站恢复时也会一并还原。

### 6.4 搜索

1. 点顶部搜索框（或在软件前台按全局热键 `Ctrl+Shift+P`，光标自动进搜索框）。
2. 输入关键词（支持中文/英文/多个词），**停止输入约 1.5 秒后自动搜索**（V1.8.0 起改为"停顿才查"，避免边打边刷、卡顿）；匹配的是条目的**全部文字字段**。
3. 想立刻出结果：点搜索框右侧的 **🔍** 小图标，或按 **回车**。
4. 清空搜索框 → **回到你进入搜索之前的那个浏览视图**（V2.0.0 修复：此前会停在旧搜索结果里不动）。
5. **V2.0.0 新增：支持 `#标签` 语法**——在搜索框输入 `#` 加标签名（如 `#赛博朋克`），只列出带该标签的条目；标签的详情见第 13 章。

> 为什么要等 1.5 秒？以前每敲一个字符就要把整库搜一遍并重画列表，输入长句时会明显卡顿。现在改成"你停手了我再查"，体验更顺畅。

### 6.5 复制提示词（中文 / 英文 / 全部）

1. 选中条目。
2. 在详情区复制行点按钮：
   - **📋 复制全部** = 名称 + 全部字段一起复制（最常用）。
   - **复制中文** = 只复制⑧中文版提示词。
   - **复制英文** = 只复制⑨英文版提示词。
   - ⑩ 图像获取方案 如果填的是网址，可点它旁边的"打开"按钮直接调浏览器打开。
3. 复制成功后，到 AI 对话框里按 `Ctrl+V` 粘贴即可。

> 隐私提醒：剪贴板内容对你电脑上当前正在运行的所有程序都是可见的（这是 Windows 的机制），请不要复制敏感信息。

### 6.6 条目的"多位置"：关联到 / 复制到 / 移动到

一条提示词可能既适合放"人像"分类、又适合放"夜景"分类。软件给你三种玩法，务必分清：

| 操作 | 是什么 | 后果 | 典型用途 |
|---|---|---|---|
| **↔ 关联到…** | 让"同一条内容"同时出现在多个分类 | 位置变多，但**只有一份**：在任何位置改，其它位置同步变；删除后所有位置一起消失 | 一条内容想被多处查到 |
| **⧉ 复制到…** | 为每个目标分类做一份**独立的副本** | 位置多、内容也多份，各自独立修改（含图片副本）互不影响 | 想在别处改出一版"变体" |
| **➜ 移动到…** | 把当前位置搬到目标分类 | 默认只搬当前这处（其它关联位置保留）；勾选"整体转移"则清空其它位置只留新位置 | 放错地方了，挪个窝 |

- 操作入口：选中条目后点详情区的"➜ 移动到… / ↔ 关联到… / ⧉ 复制到…"，会弹出目标选择窗口（按 项目类别 → 根目录 → 分类 组织，可多选）。
- 在"搜索 / 常用 / 未分类"视图里操作"移动到"，按整体转移处理。
- 想确认一条内容到底在几个地方？看详情区顶部的**位置面包屑**：主位置浅绿色，关联位置浅灰蓝色，每个关联位置都可点"×"单独解除。

### 6.7 删除一条提示词（会先进回收站，别怕）

1. 选中要删的条目。
2. 点详情区底部"🗑 删除当前条目"。
3. 弹窗第一次确认：如果这条同时存在于多个位置，会明确提示"删除后将在全部位置消失"。
4. 弹窗第二次确认：告诉你"确定移入回收站？可随时恢复"。
5. 删除完成。此时它**不是真的没了**，而是进了"♻ 删除历史/回收站"（第 7.3 节），随时能一键恢复原样。

> 为什么删个东西要问两次？——防手滑。数据无价，多点一下"是"的耐心值得。

### 6.8 删除分类（三级保护 + 确认短语）

删除"分类"比删除"条目"危险得多（一个分类下面可能挂着成百上千条），所以软件设了**三级保护**：

**第一级：有下级子分类 → 不允许直接删**
如果这个分类下面还有子分类，弹窗会告诉你"还有 N 个子分类，不能直接删除"。两条路：
- 先逐个处理（删除/移走）下级分类，变成"无子分类"状态再删；
- 或者点【是】进入**级联删除**（把这一整棵分类树连同内容一次性处理）。

**第二级：无子分类 → 安全删除**
弹窗问"确定删除分类【xxx】？它的 N 条本级条目将仅解除在本分类的关联（没有其它位置的条目会转到「未分类」，**条目数据全部保留**）"。点"是"即删除分类本身，但**里面的数据不丢**，只是被"打散"到未分类。

**第三级：级联删除 → 必须输入确认短语 + 最后再确认**
如果你选择把整棵分类树（含全部下级分类）一并删除，软件会要求**手工输入确认短语**才能继续：

1. 弹窗显示将删除哪些分类、有多少条直挂条目将移入回收站；
2. 要求**输入确认短语：「删除全部下级内容」**（这是固定的四个字，必须一字不差）；
3. 短语输对后，还会再弹一次"🚨 最后确认：分类结构将**永久删除**，相关条目移入回收站，确定删除？"；
4. 点"是"才真正执行。分类结构删除后不能从回收站恢复整棵树，但**其中的条目先进了回收站，彻底清除前可恢复**。

> 一句话总结：删分类要过三道闸（有子分类先拦一道 → 删分类本体确认一道 → 级联删除还要输短语+最后确认）。只要你没有"主动输入短语并点两次是"，数据就还在。

## 7. 数据安全

### 7.1 自动全量备份（每次启动自动做，几乎不用你管）

**什么时候做**：每次打开 PromptSprite 时，软件自动把当前整个数据库复制一份到 `data\backup\`，名字像这样：

```
prompts_2026-09-09_08-30-15_483506.db   （prompts_年月日_时分秒_微秒.db）
```

**几条规则（V1.7.0 起）**：

1. **按天去重**：同一天只保留最后一份。哪怕你今天开机 10 次，也不会生成 10 个文件，只留今天最后那次的一份——省空间又不乱。
2. **默认保留最近 30 份**：超出 30 份（约一个月的跨天回滚窗口）后，最老的自动删除。份数可在 **⚙ 设置 → 自动备份保留份数** 里修改（改成比如 60、90 都行，前提是磁盘够）。
3. **只清理"标准命名"的备份**：`prompts_日期_时间.db` 这种才在自动清理范围里。
4. **手动快照（snapshot_*、*_施工前_* 等）永不自动清理**：你亲手复制的保险文件，软件绝对不动。
5. **备份失败有提示**：如果磁盘满了等导致备份失败，启动后底部状态栏会显示"● 备份失败：…"的黄点警告——看到它请尽快清理磁盘或检查 `data` 目录权限。

**怎么用自动备份恢复数据？**：关闭软件 → 挑一个想回到的日期的 `.db` 文件 → 复制去覆盖 `data\prompts.db`（建议先把现在的 `prompts.db` 改名备份一份）→ 重新打开软件。

### 7.2 手动快照：大动作之前的"后悔药"

自动备份是"每次启动"才做的。如果今天你打算做一次大规模整理（比如删一批分类），建议**先做一次手动快照**：

1. 关闭软件；
2. 复制 `data\prompts.db` → 粘贴到 `data\backup\` 文件夹；
3. 把副本改名，例如 `snapshot_整理前_20260909.db`；
4. 重新打开软件，放心干活。

因为名字不是标准备份名，**软件永远不会自动删除它**，你要留多久都行（占空间而已，一份约几 MB 到几十 MB）。

### 7.3 回收站 / 删除历史（恢复 / 彻底删除 / 清空）

入口：详情区底部 **"♻ 删除历史/回收站"**。

这个窗口就是"被删除条目的大本营"，每条显示：**名称、原位置、删除于什么时间、来源**（手动删除 / 级联删除 / 导入同步删除等）。

三个按钮的含义要分清楚：

| 按钮 | 作用 | 后果 |
|---|---|---|
| **↩ 恢复** | 把这条从回收站放回原处 | 原内容、收藏、所在位置全部还原；如果它原来的分类已被删掉，则恢复为"未分类" |
| **彻底删除** | 从回收站移除这一条 | **不可恢复**！连同它关联的图片文件一起释放（**V2.0.0 起，条目图集里的本地图片文件也会一并释放**） |
| **🗑 清空回收站** | 把回收站里所有条目一次性彻底删除 | **不可恢复**！请先确认没有想找回的（**V2.0.0 修复：清空时会同步释放图集的本地图片文件，不再残留孤儿文件**） |

要点：
- 删除条目时只是"移入回收站"，条目对应的**图片文件也还留着**，直到"彻底删除/清空"才释放。
- **V2.0.0 起**，回收站"批量入站"的条目（来自变更包删除同步）其**标签、自定义字段取值、图集**都会随快照一起保存，恢复时不会丢（修复了此前会丢的问题）。
- 锁定状态（🔒）下这个窗口只读，恢复/删除按钮全部禁用。
- 平时回收站里有几条没处理完全没关系，不占多少空间；建议隔一段时间清空一次。

### 7.4 查看"新增历史"（最近录了什么，一目了然）

入口：详情区底部 **"🕒 新增历史"**。

- 按 **今日 / 近 3 天 / 近 7 天 / 近 30 天 / 全部** 分段查看最近新增的条目。
- 每条都可以一键复制提示词（复制中文 / 复制英文 / 复制全部），方便速取、自查工作量。
- 只读窗口，锁定状态下同样可看。

## 8. 每日"变更包"

> 这一章是 V1.7.0 的重头戏，也是新手最容易懵的地方。我们拆成五个小问题慢慢讲：**是什么？什么时候生成？文件名怎么看？怎么拷到另一台电脑合并？导入时那几个选项到底选哪个？**

### 8.1 它是什么？什么时候自动生成？

**是什么**：PromptSprite 每天帮你记一笔"账"——把**今天这一天里**你对数据做过的所有改动（新增了哪些、删除了哪些、改动了哪些分类）打包成一个 JSON 文件，叫**当日变更包**。它是"当天变化"的记录，不是全量数据。

> 打个比方：全量备份像"每天给整本书拍照"，变更包像"每天记一行日记：今天加了 3 页、撕了 1 页"。

**什么时候自动生成**：**每次正常关闭软件时**自动执行（也就是"正常使用时自动生成"，你不用点任何按钮）。

- 存储位置：`data\backup\incremental\`
- 当天如果**没有任何变化**（没新增、没修改、没删除），就不会生成新文件（这是正常的）。
- 当天有变化、后来又改了：关软件时会**重新生成**同一个"当日文件"，永远保证**每台电脑每天只有一个变更包**，内容=当天全部变更。
- 保留规则：默认只保留最近 **30 天**（在 ⚙ 设置 → 变更包保留天数 可改）。老版本软件生成的"增量_xxx.json"文件也会被一起按 30 天清理。
- **V2.0.0 起，变更包记录的内容更全**：除了条目正文与分类，还会记录**标签、自定义字段取值、条目图集**，并**随包携带字段定义（field_defs）**——换到另一台电脑导入后，自定义字段既"有定义"也"有取值"。另外，如果你**打了标签、改了/删了自定义字段**，条目的修改时间会被正确刷新，这些改动就会进入当天的变更包（修复了此前可能"静默漏同步"的问题）。

### 8.2 文件名的含义：`变更包_{电脑代号}_{日期}_add_{N}_del_{M}.json`

完整格式：

```
变更包_电脑代号_日期_add_新增条数_del_删除条数.json
```

举三个真实例子：

| 文件名 | 一眼能看出什么 |
|---|---|
| `变更包_DESKTOP-hahaha_2026-09-09_add_3_del_0.json` | 电脑 DESKTOP-hahaha 在 09-09 当天**新增/修改了 3 条，没删任何条目**（纯新增包，安全） |
| `变更包_DESKTOP-hahaha_2026-09-09_add_1_del_1.json` | 当天**新增 1 条、删了 1 条**（有增有删的混合包） |
| `变更包_DESKTOP-053MORJ_2026-09-08_add_0_del_1380.json` | 当天**一条没加、却删了 1380 条**——这是"**纯删除包**"，俗称**负增量**（见 8.4 节的警告），拿到这种文件要格外小心！ |

数字代表什么：

- `add_` 后面的数字 = 当天**新增/修改的条目条数**（按"条"计）。说明：目前软件判断"是不是同一条"靠内容比对，"修改一条"在变更包里会表现为"新增一条同内容的新条目 + 保留原条目"。
- `del_` 后面的数字 = 当天**删除的条目条数**。
- **分类、根目录的增减不算进文件名**（它们记在文件内部的摘要 summary 里，导入预览时会显示出来）。
- 一句话：**光看文件名就能判断这个包是"会让我变多"还是"会让我变少"**——这是 V1.7.0 专门吸取 9-8 事故教训加的（以前叫"增量备份"，让人误以为只会加数据）。

### 8.3 怎么把这个文件拷到别处 / 给别人

有两个入口，效果不同：

1. **⇧ 导出 → 导出当日变更包文件到…**
   - 只导出"今天"自动生成的那个变更包文件，可存到 U 盘/网盘/发给另一台电脑。
   - 导出前会先弹一个小窗"对账"：显示文件名、新增/修改几条、删除几条。
   - ⚠️ **负增量警告**：如果今天只删没加（`add_0`、`del_>0`），会弹红色警告窗"该变更包为当日仅删除数据的‘负增量’包，请谨慎分发/导入！"——意思是：这个包拷给别人，**只会删掉对方的数据，不会给对方加任何东西**。看清楚再发。
2. **⇧ 导出 → 变更包数据导出 Excel… / HTML…**
   - 选一个变更包文件，把它转成 Excel 或网页，方便**打开浏览**里面的内容、或发给不想装软件的人看（转换过程在临时库里进行，不影响你当前数据）。

### 8.4 换机合并：把变更包导入另一台电脑/副本（重点！）

**场景**：你办公室电脑（代号 `OFFICE-PC`）今天录了 20 条新提示词，关软件时自动生成了 `变更包_OFFICE-PC_2026-09-09_add_20_del_0.json`。晚上回家想在**家里电脑**上也看到这 20 条。

**操作步骤**：

1. 在办公室电脑：⇧ 导出 → 导出当日变更包文件到… → 把文件存到 U 盘（或发给自己）。
2. 回家打开家里电脑上的 PromptSprite。
3. 点顶部 **⇩ 导入** → **导入变更包…（新增/删除合并）**，选择 U 盘里那个 json 文件。
4. 软件先弹出**导入预览**窗口，把包里的"账"念给你听：
   > 来源电脑：OFFICE-PC　　日期：2026-09-09
   > 包内新增/修改：条目 20、分类 2、根目录 0
   > 包内删除清单：条目 0、分类 0、根目录 0（或"本包不含删除清单"）
5. 确认无误后，按下面 8.5 节的两条选择来勾选，点"开始导入"。
6. 完成：底部提示导入结果；回到书架就能看到新条目。

**重要提醒（第 9-8 事故的教训，务必看）**：变更包≠只会加数据。它可能是个**删除包**（负增量）。如果你把自己 9 月 1 日的老全量库，直接导入一个 9 月 8 日的删除包，软件会按删除清单把"内容相同"的条目从老库里删掉——条目数不升反降（真实测试中 3987 条被删到 2607 条）。**所以导入前一定要看预览**，并想清楚下面两个问题。

### 8.5 导入向导的两个选择（V1.7.0，全用大白话解释）

预览窗口里真正要你决策的，是**两个正交的选项**，互相不冲突：

**第①个选择：要不要"导入并合并包内新增/修改条目"？（一个复选框，默认已勾选）**
- 勾上 = 把包里的新内容加进这台电脑（推荐）。
- 不勾 = 只处理删除清单，不加任何新内容（极少用）。

**第②个选择：包里的"删除清单"怎么处理？（三选一，单选按钮）**

| 选项 | 大白话 | 什么时候选 | 需要输入确认短语吗 |
|---|---|---|---|
| **忽略删除（不删任何现有数据，推荐）** | 假装没看见删除清单，一条都不删，只进新的 | **默认推荐。** 你不确定这台电脑是否同步过对方的历史删除时，永远选它最安全 | 不需要 |
| **正常应用删除（把清单中内容从本库删除，需确认）** | 让本库"跟上"来源机：凡是清单里点名要删的内容，只要本库里有相同内容，就一起删掉（先移入回收站，可恢复） | 这台电脑和来源机**长期保持同步**、你想让两台完全一致时 | 需要输入短语「**确认删除**」 |
| **逆向恢复已删除数据（把清单中携带快照的内容重新导入，需确认）** | 反向操作：把"当初被删掉的内容"重新加回来（救援功能） | 你想找回数据、且包里带被删内容的完整快照时（见第 9 章）。**若包里没带快照，这个选项是灰的**，提示只能靠回收站/历史备份 | 需要输入短语「**恢复删除**」 |

**三个必须懂的安全机制**：

1. **确认短语 = 最后一道闸**。选"正常应用删除"要亲手输入「确认删除」；选"逆向恢复"要亲手输入「恢复删除」。输错或取消 = 不执行。这是逼你在点确定前再想一遍。
2. **导入前自动快照 = 后悔药**。只要执行"应用删除"或"逆向恢复"，软件都会**先自动生成一份 `prompts_preimport_日期时间.db`** 放在 `data\backup\` 里，然后再动手。万一后悔：关闭软件 → 用这个文件覆盖 `data\prompts.db` 就能回到导入前。这个文件以 `prompts_preimport_` 开头，**不会被自动清理**。
3. **落后提示 = 危险预警**。如果目标电脑的最后同步时间早于变更包日期（说明这台电脑可能还没同步过来源机的历史删除），预览窗口顶部会出现红字：
   > ⚠ 提示：目标库最后同步时间早于本变更包日期，可能尚未同步来源机的历史删除；如无把握请把删除处理选为"忽略删除"。
   看到红字，乖乖选"忽略删除"就对了。

**还有两个补充说明**：
- 同步删除的内容**先进回收站**（可恢复、图片保留）；但**被删的分类结构**是直接删除的，不随回收站恢复。
- 导入普通"JSON 备份"如果发现文件其实是个变更包/带删除清单，软件会自动改走这个导入向导，不会让你盲导。

### 8.6 一个完整的"灾难救援"小例子（体会负增量/逆向恢复）

假设你的数据出过这种事：

- 9 月 1 日：你有 2500 条（只剩这一天的全量备份）。
- 9 月 4 日：加了 1000 条 → 3500 条。
- 9 月 5 日：当天新增 100 条、又删掉了 9 月 4 日那批里的 500 条 → 当天变更包文件为 `add_100_del_500`。
- 9 月 9 日：系统坏了，你手里只有 9 月 1 日的全量备份和 9 月 5 日的变更包。

问：现在最多能恢复到多少条？

答：**2600 条**。做法：先导入 9 月 1 日全量库，再导入 9 月 5 日变更包时选"①合并新增"+"②忽略删除"。为什么不是 3100？因为那被删的 500 条在 9 月 1 日的备份里本来就不存在（它们是 9 月 4 日才加的），"删除清单"在你库里一条都命中不了，不会变少；而真正缺的，是 9 月 4 日新增、9 月 5 日**没删**的那 500 条——它们不在 9 月 1 日的全量里、也不在 9 月 5 日的变更包里（9 月 5 日没动它们），**任何魔法都补不回来**，只能靠 9 月 4 日的备份/变更包/删除那台机器自己的回收站。

**结论（长期正确姿势）**：
1. 平时让软件自动做全量备份（30 份）+ 每日变更包（30 天）都开着，别关；
2. **定期**把"全量 JSON 导出"或备份 `.db` 文件复制到网盘/U 盘（异机异地最保险）；
3. 有了"某一天的全量 + 之后每一天的变更包"，理论上可以**向前重建**到任意一天；
4. "逆向恢复"是极端情况下的补救手段，不是日常主路径。

## 9. 变更包携带被删快照

### 9.1 它是干什么的？

开关位置：**⚙ 设置 → 变更包携带被删快照**（默认**关闭**）。

- **关闭（默认）**：变更包的删除清单里只记录被删条目的"名字 + 内容指纹"，**不含完整内容**。好处是文件小、而且"已删除的内容"不会跟着包到处分发；代价是拿到这个包的人无法逆向恢复（只能靠目标库自己的回收站/历史备份）。
- **开启**：软件在生成每日变更包时，把**被删条目的完整内容（快照）也塞进包**。这样把包导入其它电脑时，就能用第 8.5 节的"逆向恢复"把当初删掉的数据重新加回来。

### 9.2 开启它，界面上的红字会告诉你代价

设置窗口里这个开关下面有一行**红色小字**，原文大意：

> ⚠ 开启后变更包内会包含"已删除"的内容（体积增大、含敏感数据），但可在导入时使用"⑤ 逆向恢复"找回被删数据。

翻译成大白话，你要权衡三点：

1. **体积变大**：快照是完整内容，会明显增大包文件；
2. **隐私风险（最关键）**：如果当初删除这批数据就是为了"清理私人内容/防止泄露"，那开着这个开关 = 把"你已删除的隐私"又装回包里带走分发——**负增量包会变成隐私泄露包**。所以默认关闭；
3. **可能找回"当时有意删除"的数据**：逆向恢复会把当初**故意删掉**的内容也加回来。所以"逆向恢复"执行前要输入确认短语「恢复删除」，弹窗里也明说了"可能包含当初有意删除的数据"，想清楚再输。

**给你的建议**：日常**保持关闭**即可。真遇到"只有变更包、没有别的备份、还想找回被删内容"的极端情况，再临时开启让它生成一次携带快照的包，用完记得关回去。

## 10. 数据比对

### 10.1 这是干什么的？

V1.7.0 新增的**只读诊断**功能：拿"当前的数据"和"某一天自动备份的 \*.db 文件"比一比，一目了然地看出：

- 备份里有、现在没有了（= 这段时间被删的）；
- 现在有、备份里没有（= 这段时间新加的）；
- 分类/根目录/项目类别的增减；
- 条目内容变化（按名称 + 内容比对）。

### 10.2 怎么用

1. 点 **⇩ 导入** → 菜单最下面 **数据比对…（与备份 \*.db）**。
2. 在文件选择框里挑一个备份文件，例如 `data\backup\prompts_2026-09-01_...db`（自动备份和手动快照都是 \*.db，都能比）。
3. 窗口会先给"差异概览"（新增多少、删除多少、当前共多少条、备份共多少条），下面是**差异明细列表**（每条显示：差异类型 / 名称 / 所在分类链）。
4. 可点"导出差异报告（HTML）"，存成一个网页文件方便留存或发给别人看。

**安全保证**：
- **全程只读**：软件先把要比较的备份复制到临时文件再打开，**绝不写入你的主数据库**，放心用；
- 比较的条目按"内容指纹"判断是否同一内容，只看差异、不改任何东西；
- 锁定状态下此功能不可用（因为它需要读取，且属于菜单诊断功能）。

**用途举例**：你怀疑"导入某个变更包后数据变少了？"——不必瞎猜，用这个功能把当前库和一个导入前的自动备份（或导入前快照 `prompts_preimport_*.db`）比一下，少了哪些条目、哪些分类，列得清清楚楚。

## 11. 老版本数据迁移

如果你是 PromptSprite 老用户，数据是老版本结构（根目录-一级-二级，还没有"项目类别"这一最高层），升级到新版本后软件这样处理：

**第 1 步：数据库自动升级（不用你管）**
打开软件时，程序会自动检查并补全新版需要的表/字段（幂等迁移，可反复打开），老数据不会丢。

**第 2 步：根目录归属整理（可能需要你点几下）**
老版本的根目录没有归入"项目类别"，会暂时显示在"项目类别"列最底部的"🗂 未分配"里。此时：

- 启动时若检测到存在"未分配"的根目录，会自动弹出 **数据迁移向导**（若你上次点过"取消"，之后不再自动弹，但可手动打开）；
- 手动打开：**⇩ 导入 → 数据迁移向导…**。

**在向导里做什么**：
1. 表格列出所有未归属的根目录，每一行右边有个下拉框让你选"归入哪个项目类别"（**默认值已按软件内置的映射表帮你预填好了**，多数情况直接点执行即可）。
2. 点"执行迁移"：已选择的按你选的归入；没匹配映射的默认归入"未明确分类"。
3. 点"取消"：什么都不改（根目录继续留在"未分配"，以后随时可再开向导）。

> 注意：无论怎么选，**你的条目数据都不会丢失**，只是根目录的"归属大堆"变了。迁移完成后，"未分配"消失，所有根目录都进了某个项目类别。

## 12. 常见问题 FAQ

### 12.1 我找不到 `data` 文件夹在哪里？

- **用 EXE**：`data` 就在 `PromptSprite.exe` 的**同一个文件夹**里。如果你是通过"快捷方式"启动的，请去快捷方式指向的**真正存放 EXE 的文件夹**里找。
- **从源码运行**：`data` 在项目根目录（和 `app` 文件夹平级）。
- 还找不到？打开软件，右上角 ⚙ 设置 → ℹ 关于，里面会显示"程序路径"，`data` 就在那个路径下。

### 12.2 换电脑/换文件夹后，为什么数据是空的（全新模板）？

因为你只复制了 EXE，没复制 `data`。软件在没有任何 `data` 的情况下首次运行，会自动生成内置模板库（全新数据）。

**正确做法**：把**整个文件夹**（含 `data`）一起拷走。保险起见，平时就把 `data` 里的 `prompts.db` + `backup` 文件夹定期备份到网盘/U 盘。

### 12.3 误删了数据怎么办？

分几种情况，按顺序试：

1. **刚删的条目**：详情区底部 **♻ 删除历史/回收站** → 找到那条 → 点"↩ 恢复"（内容/收藏/位置原样回来）。
2. **删了分类（安全删除）**：条目没丢，只是被"打散"到 **📂 未分类** 里，去那里找。
3. **级联删了一大片 / 导入删了一大批**：
   - 回收站里应该躺着那些被删条目，先恢复；
   - 如果是在"导入变更包"之后发生的，用导入前自动快照 `data\backup\prompts_preimport_*.db` 覆盖 `prompts.db` 整体回滚（第 8.5 节）；
   - 再不行，用启动自动备份里**最近的一份** `prompts_日期.db` 回滚（第 7.1 节）。
4. 都没救回来？——那就只剩"彻底删除"之前你手动复制出去的备份了。**再次强调：重要数据请定期异机备份。**

### 12.4 导入一个包之后，条目数反而变少了？！

先别慌，按下面三步排查：

1. **看预览数字（最重要）**：V1.7.0 起导入"变更包"前必有预览窗，会明说"包内删除清单：条目 X、分类 Y"。如果你导入的是一个 `add_0_del_1380` 之类的**纯删除包（负增量）**，条目变少是**符合预期的**——它本来就是个"删除清单"，不是"增加包"。不想删，就选"忽略删除"再导一次。
2. **看回收站**：执行了"正常应用删除"的条目先进回收站（可恢复）；还有导入前自动快照 `prompts_preimport_*.db` 可整体回滚。
3. **看是不是显示问题**：数据其实没少，只是
   - 你现在停在"搜索/常用/未分类"视图里，回到 **项目类别列逐级点** 再看；
   - 或者一些字段因为"详情字段显示=自动"被隐藏了（第 5.3 节）——在 ⚙ 设置里改"全部显示"即可看到全部字段，数据一直还在库里。

### 12.5 为什么有些条目的"③~⑦"字段看不到？

多半是"详情字段显示"设成了**自动**（默认）。V2.0.0 起这个设置**真正生效**了：默认"自动"下，**只有"视频""图像"两个根目录会完整显示 ②~⑦，其余根目录只显示 ② 介绍**。想临时全部看见：点详情区头部"⏵ 显示全部字段"（只对当前这次生效）；想长期全部看见：⚙ 设置 → 详情字段显示 → **全部显示**。（数据一直都在库里，只是"显示多少"的差别。新增时想填 ③~⑦，点表单里的"展开"那一组即可。）

### 12.6 删了条目/图片会一起没吗？

不会立刻没。删除条目 = 移入回收站，**图片文件保留**；只有你在回收站里点"彻底删除"或"清空回收站"时，图片文件才会一并释放（**封面与图集里的本地图片都算**；外链图只是网址，不涉及本地文件）。另外"⧉ 复制到"会为副本生成**独立的图片副本**。

### 12.7 为什么点删除/保存/导入都是灰的、点不动？

因为你开着 **🔒 锁定**（按钮显示红色"🔓 已锁定"）。锁定状态下软件只允许查看、搜索、复制，所有写操作（新增/编辑保存/删除/移动/导入/快速新建）一律禁用——这是防误操作保护。点一下"锁定"按钮解锁即可。

### 12.8 全局热键 `Ctrl+Shift+P` 没反应？

热键注册失败常见原因：

- 热键被其它软件占用；
- 权限不足（普通权限下某些环境注册不了全局键）——**以管理员身份运行一次**试试；
- 被杀毒软件拦截——把软件加入白名单。

热键失败不影响正常使用（点窗口、用按钮都行）。

### 12.9 软件打不开 / 启动闪退 / 没反应？

按顺序排查：

1. 路径是否含中文/特殊字符 → 放到纯英文路径（如 `D:\PromptSprite`）；
2. 杀毒软件拦截 → 加入白名单后重新解压/运行；
3. EXE 是否被下载工具损坏 → 重新下载；
4. 从源码运行时依赖没装好 → 手动执行 `pip install -r requirements.txt`；
5. 查看 `data` 所在磁盘剩余空间是否足够。

### 12.10 状态栏出现"● 备份失败"？

说明这次启动的自动备份没成功（最常见是磁盘空间不足或 `data\backup` 写入权限问题）。请清理磁盘空间或检查目录权限，下次启动软件会自动重试。

### 12.11 找不到今天的"变更包"文件？

当天没有任何数据变化（没新增/修改/删除），关软件时不会生成文件，这是正常的。随便新增一条再正常退出，就能在 `data\backup\incremental\` 看到今天的 `变更包_*.json` 了。

### 12.12 Excel 文件太大导入很慢/卡？

Excel 导入已用流式读取方式处理，但超大文件仍需要时间。文件特别大时建议拆分成几个文件分批导入，或改用 JSON 格式导入。

### 12.13 V2.0.0 升级后，我的老数据/老备份还能用吗？

能，而且**不用做任何迁移**。本轮所有改动都是"**纯新增表 / 纯新增字段**"：

- 库结构只升到 **schema v4**（新增 6 张表），老数据原样保留、打开软件时自动补表；
- 导入导出格式升到 **JSON v5**，但**旧备份、旧导出文件（JSON v2/v3/v4、旧 Excel 模板、MD 手册）仍可直接导入**；
- 数据文件名（`data/prompts.db`、`backup/`、`images/`、`变更包_*`）**一律未改**，老用户的数据、备份、变更包、图片都无需迁移。

### 12.14 "从网址获取"联网抓取安全吗？能抓哪些、抓不了哪些？

**只在你主动点"从网址获取"并给出网址时才会联网**，工具只做"下载你指定的网页/文件并解析成表"，不上传、不外发你的任何数据。

能抓：普通网页里的 HTML 表格、GitHub 上的单个文件、GitHub 目录下的批量文件（常见文档格式）。
**抓不了 / 不做的**（见 12.15 已知限制）：需要 JavaScript 渲染才出现内容的页面、需要登录才能看的页面；工具也不会去绕过网站的风控、不会自动爬取整站。

### 12.15 V2.0.0 已知限制与注意事项

1. **联网抓取**：不支持需 JS 渲染的页面；不处理登录；不做风控绕过；不做站内遍历；部分站点需要你手动补 **Referer / Cookie** 才能取到内容。
2. **"标签"类型自定义字段**：按**文本**保存（多个标签用逗号分隔），可被搜索 / 导出 / 变更包自动覆盖；**未做"字段级独立标签体系"**（与第 13 章的标签系统是两回事）。
3. **"图像"类型自定义字段**：为"**路径 + 选择 / 打开 + 内嵌缩略预览**"；**预览只读本地文件**——外链（http/https）为省流量**不下载预览**，请用"打开"在浏览器查看；路径不存在时显示灰字占位。
4. **向导出口为"先保存数据文件、再导入"**：保存后如果你又改了层级映射 / 换了表 / 换了数据源，需要**重新保存**文件再导入。

### 12.16 为什么我（老用户）升级后没看到"预置标签"？（V2.1.0）

因为软件**不会覆盖你已有的数据**。V2.1.0 的内置库里虽然已经预置了标签（622 个标签 / 6579 条关联），但**只有当 EXE 旁边还没有 `data\prompts.db` 时**（也就是全新安装）才会把这份内置库复制过去；你原本的库里有自己的数据，软件绝不会替换它。

想给现有数据加上标签，请用**软件自带的批量打标**（推荐，安全且可撤销）：

1. 打开**标签页面**（工具栏 🏷 或详情区底部 🏷）→ 底部「🤖 批量打标…」；也可以走「⚙ 设置 → 标签与词表 → 🤖 批量智能打标…」；
2. 先点「🔍 预演（不写库）」看结果，满意后点执行（**执行前会自动备份数据库**）；
3. 不满意就点「↩ 撤销本次打标」精确回退（详见第 20.2 节）。

> 不要为了拿预置标签而删除自己的 `data\prompts.db`——那等于丢掉全部数据（除非你事先做好了完整备份）。

### 12.17 批量自动打标会不会把我手工打的标签冲掉？能撤销吗？（V2.1.0）

- **不会冲掉**（只要你选对选项）：打标对象默认是「**仅无标签的条目**」（有标签的会被跳过）；写入策略默认「**追加（并入既有标签）**」，只有你手动改成"覆盖"才会替换；
- **必须先预演**：没预演就点执行会被拦下（预演是"只读"的，不改任何数据）；
- **执行前强制自动备份**：备份失败会**直接中止、不写入任何数据**；
- **可精确撤销**：每次执行都会留下"打标批次"明细（`data\backup\tagging\打标批次_<时间戳>.json`，只保留最近 10 个），在「🕒 历史批次…」里点"撤销"即可**只回退这一次打标**，不影响你之后的其它修改；
- 但要清楚一件事：打标会让条目的"修改时间"刷新，所以**被打标的条目会进入当天的"变更包"**（执行前的二次确认弹窗会如实提示"这 N 条会被计入今日变更包"）。

### 12.18 我想让标签词表多一个"学术"大类，能自己加吗？（V2.1.0）

**能，而且不用改代码、不用重装软件**。词表的"权威数据"存在数据库里，可以在软件内导出→编辑→导入：

1. 打开标签页面 → 切到「**词表**」页签（或 ⚙ 设置 → 📚 词表管理…）→ 点「⬆ 导出词表…」，得到一个 JSON 文件；
2. 用记事本打开它，在 `domains` 里照着"视觉 / 文学 / 编程"的样子**再加一个键**（例如 `学术`），里面按维度写好标签名与匹配词；
3. 回到软件点「**⬇ 导入词表…**」选中这个 JSON：软件会**先校验结构**（不合法直接拒绝、不写入），校验通过则**先自动备份当前词表**再导入；
4. 如果改坏了，点「**↺ 恢复出厂词表**」即可回到出厂的 135 个标签。

详细操作见第 20.3 节。

### 12.19 V2.1.0 已知限制与注意事项

1. **预置标签只随"全新安装"下发**：老用户的现有数据库不会被自动补标签，需要在软件内用「批量打标」自行生成（见 12.16）；
2. **热点词的"来源网址"默认留空**：需要你自己填写要抓取的来源网址；抓取失败不会阻断（只是那一次不追加），词条初始为空；
3. **词表导入是"整份替换"**：导入的 JSON 会整体替换当前词表，因此**导入前请确认结构完整**（软件会先校验 + 自动备份，但不做"合并"）；
4. **自动打标是"规则匹配"而非大模型推理**：它按词表的匹配词与三源优先级打标，结果可预期、可复现，但**不会理解语义**；词表里没有的词就打不出来，需要自己补充词表；
5. **性能上限**：条目区与标签页面默认只显示前若干条，是为了让界面"秒开"；需要看全时可点「▼ 显示更多」或「全部显示」（超过 500 条会先二次确认，避免长时间卡顿）。

## 13. 标签系统与标签页面（V2.0.0 新功能）

> 本章是 V2.0.0 新增。**标签** = 给条目贴的"关键词便利贴"，一条可以贴多个、还能跨分类聚合。它和"四级分类（目录）"不是一回事：**目录决定条目"住在哪"，标签决定条目"还能被哪些主题找到"。**

### 13.1 在详情区给条目打标签（🏷 标签区块）

1. 选中条目，详情区里找到 **🏷 标签** 区块。
2. 在输入框里输入文字：
   - **输入会自动补全已有标签**——打几个字就弹出匹配的旧标签，点一下即选中，避免"同一个标签写成好几种写法"；
   - **回车即可新建**一个全新标签并贴到这条上；
   - 每个已贴标签旁边有 **×**，点一下移除。
3. 标签随条目一起保存；复制条目、关联/复制/移动、进出回收站时都会一并带上。

### 13.2 标签页面（两个入口）

- **入口一**：顶部工具栏 **🏷 标签页面** 按钮。
- **入口二**：详情区底部常驻栏的 **🏷** 小图标。
- **与"四级目录"互斥**：打开标签页面会自动收起左侧四级目录；反过来点"🗂 目录显示"回到目录时，标签页面也会自动关闭。两条关闭路径（底部 🏷 / 工具栏 🗂）行为统一，都会**复位到打开前的那个视图**（V2.0.0 修复）。

标签页面里你能做：

| 功能 | 说明 |
|---|---|
| **两种呈现** | **标签云 ⇄ 列表＋计数徽标**，一键切换，软件**记住你上次的选择** |
| **且 / 或 组合过滤** | 同时选多个标签时，可选"**且**（同时含有）"或"**或**（含有任一个）" |
| **排序** | 按**名称**或按**计数（条目数）**排序 |
| **维护** | **重命名 / 合并 / 删除 / 清理未使用**（把没有任何条目引用的空标签一次清掉） |

### 13.3 设置项"在条目处显示标签"（默认关）

⚙ 设置 → **在条目处显示标签**：打开后，条目卡片/列表上会直接显示它的标签（默认关闭，避免列表太挤）。

### 13.4 用 `#标签` 搜索

搜索框支持 `#标签名` 语法：输入 `#赛博朋克` 只列出带该标签的条目（详见 6.4 节）。

> 提示：第 15 章还有一类"**标签类型的自定义字段**"——那是"某个字段的值是一串逗号分隔的标签文本"，与本章这套"跨条目的标签系统"不是同一个东西，别混淆。

### 13.5 V2.1.0 更新：标签页面现在是"四个页签"

**V2.1.0 起**，标签页面顶部多了一个切换器，共 **4 个页签**（V2.0.0 时只有"标签云 / 列表"两档）：

| 页签 | 里面是什么 | 会不会影响条目区 |
|---|---|---|
| **标签云** | 所有标签按"使用次数"分档显示大小，点一下即筛选（标签多时自动换行，不会只显示前几个） | 会（按标签筛出条目） |
| **列表** | 标签 + 计数徽标的列表视图，便于查找与批量治理 | 会 |
| **热点词**（V2.1.0 新增） | 维护"待匹配的热点词"清单（与标签表完全隔离，不产生标签） | **不会** |
| **词表**（V2.1.0 新增） | 查看 / 导出 / 导入标签词表结构 | **不会** |

另外，标签区右上角新增「**显示**」下拉：**前 50（默认）/ 前 100 / 前 200 / 前 500 / 全部**，用于控制一次渲染多少个标签。为什么要限制？——因为标签一多，逐个创建按钮会比较耗时；默认前 50 已经能覆盖绝大多数使用场景，需要时再放宽即可（详见第 20 章与第 21.3 节）。

### 13.6 V2.1.0：内置库已经"预置标签"（开箱即用）

**全新安装**（EXE 旁边还没有 `data\prompts.db`）时，软件复制的内置库**已经带好标签**：**2555 条条目 → 622 个标签 / 6579 条标签关联**。所以第一次打开标签页面，你会直接看到成片的标签，而不是空白。

如果你属于"**老用户**"（已经用自己的 `data\prompts.db` 在用），软件**不会覆盖你的数据**，因此看不到这批预置标签——请用第 20.2 节的「**批量打标**」给自己的数据就地补标签（可预演、自动备份、可精确撤销）。两者说明详见 **12.16** 与 **20.1**。

## 15. 自定义字段与 11 种字段类型（V2.0.0 新功能）

### 15.1 字段管理对话框

| 字段种类 | 能不能改名 | 能不能删 | 能不能改类型 |
|---|---|---|---|
| **内置 10 项**（①~⑩） | 可以改名 | **不可以删** | **不可以改类型** |
| **自定义字段** | 可以 | 可以（**归档隐藏**，不物理删除已有取值数据） | 可以 |

自定义字段支持 **增 / 删（归档隐藏）/ 改名 / 排序 / 改类型**。

### 15.2 11 种字段类型与控件

| # | 类型 | 控件与行为 |
|---|---|---|
| 1 | 单行文本 | 一行输入框 |
| 2 | 多行文本 | 多行输入框 |
| 3 | 链接 | 文本 + "**打开**"按钮（调浏览器直达） |

| 7 | 是 / 否 | **勾选框**，存为 `1` / `0` |
| 8 | 标签 | **逗号分隔的文本**，可被搜索 / 导出 / 变更包自动覆盖（见 12.15） |
| 9 | 附件 | "选择文件" + "打开" |
| 10 | 短音频 | "选择音频" + "打开" + **试听**（WAV 用标准库播放） |

### 15.3 列表框字段的三类数据源

列表框可以"跟着你的库"动态取值，共三类来源：

| 数据源 | 可选范围 |
|---|---|
| **自定义序列** | 你自己敲进去的一串固定选项 |
| **目录层级** | 选某一层级（项目类别 / 根目录 / 一级 / 二级），范围可为"**全部节点**"或"**指定子树**"，并可选择是否**显示路径前缀** |
| **条目** | "**全部条目**"或"**某分类下的条目**" |

- **单选或多选**、**是否允许新建项**都可设置。
- **被引用对象被删除后**：该字段值不会消失，而是显示占位 **"该项已经被删除（原：<快照名>）"**，你可以保留占位、**移除**它、或**重新指定**一个有效值。
- **删除目录 / 条目前会先提示**它被哪些字段引用，避免误删导致大范围"失联"。

### 15.4 字段定义会随变更包同行

从 V2.0.0 起，**变更包会随包携带字段定义**，换机导入后自定义字段"**有定义也有取值**"；"变更包导入"与"导入 JSON"都会一致地做**字段定义差异的逐项确认**（**没有差异时不会打扰你**）。详见第 8 章与第 17 章。

## 16. 网上资源结构化向导（V2.0.0 新功能）

> 这是 V2.0.0 最大的新功能：把"从网上/文件里扒下来的一堆资料"半自动地变成"四级分类 + 字段"的条目。
> 入口：主界面 **⇩ 导入 → 网上资源结构化…**

### 16.1 第 1 步：选数据来源（三选一）

| 来源 | 说明 |
|---|---|
| **粘贴文本** | 直接把 CSV / TSV / 表格文本粘进去 |
| **本地文件** | 选一个本地文件：**CSV · TSV · TXT · HTML · MD** |
| **从网址获取** | 填一个网址去抓（网页表格、GitHub 文件、GitHub 目录批量），见 16.7 / 16.8 |

### 16.2 第 2 步：层级映射 + 字段映射

- **层级映射**（四列）：**项目类别 / 根目录 / 一级分类 / 二级分类**——把来源表格的列，对到目标层级上。
  - **空单元格会继承上一行**（合并单元格的常见写法）；
  - **允许跳层**，缺少的层级按"**兜底名**"自动补齐。
- **字段映射**：把来源列对到——**内置 10 项字段 / 你的自定义字段 / 标签**。
- 页面底部还有"**③ 可选增强**"（见 16.3）。

### 16.3 第 2 步底部"③ 可选增强"（四项）

1. **行筛选**：按"包含 / 排除"关键词筛掉不要的行；筛选结果会显示在"① 数量对账"里。
2. **关键词规则 → 二级分类**：点"**编辑规则…**"，每行写一条规则，形如 `二级分类名 = 关键词1, 关键词2`；匹配时**先匹配先得**，都没命中的归入"**其他**"；可点"**检查规则**"预检。匹配范围是**整行文本**。
3. **中英提示词自动分流**：映射到 ⑧ 的中文列，如果被判定为"**以英文为主**"，会自动写进 ⑨ 英文列。
4. **同时导出 Excel**：点"① 保存数据文件…"时，会在**同目录同名**再写一份 `.xlsx`（列与"导出 Excel"一致，可被"导入 Excel"读回）。

### 16.4 第 3 步：树预览 + 统计 + 质量自检

- **树预览**：先看整理后的四级树长什么样；
- **新增 / 复用 / 判重统计**：告诉你将**新增**多少、**复用（命中已有）**多少、**判重（重复行）**多少；
- **质量自检面板**（见 16.5）。

### 16.5 质量自检面板（七项）

1. **数量对账**：源行数 → 有效行 → 条目数（含关键词筛选后的结果）；
2. **空值统计**（含自定义字段）；
3. **同分类重名**；
4. **兜底层级**（有多少条靠兜底名补齐了层级）；
5. **链接补全条数**；
6. **中英分流条数**；
7. **规则分类"其他"条数与占比**。

### 16.6 出口：先保存数据文件，再导入

向导的出口是"**先保存数据文件（JSON v5），再导入该文件**"两步：

1. 点"**保存数据文件**"，把整理结果存成一个 JSON v5 文件；
2. 再"**导入**"这个文件（导入前会**自动生成快照**，失败可**一键回滚**）。

> 注意：**保存之后如果你又改了映射 / 换了表 / 换了数据源，需要重新保存**，否则导入的还是上一次保存的文件。

### 16.7 从网址获取（联网抓取，仅在你主动使用时联网）

- **内置浏览器 UA**；高级区可填 **Referer / Cookie / 超时**（默认 **15 秒**）/ **体积上限**（默认 **10 MB**）；
- 仅支持 **http / https**；
- 自动解压 **gzip / deflate**；
- **反爬拦截页识别**：识别到拦截页会提示你补请求头；
- **失败分类提示 + 三步建议**，告诉你下一步怎么排查；
- **多通道降级**：`raw → GitHub contents API → git blob API（base64）`，**状态行会显示降级链**；
- **多表页面**：提供"**选用表格**"下拉，**默认选最大的那张表**；
- **相对链接自动补全**（含 `blob→raw` 转换），且**可以开关**；
- **两段式抓取提示**：建议**先抓索引小样确认结构，再抓正文**，避免大批量白抓；
- **抓取状态行**示例：`HTTP 200 · text/html · 4.0KB · 识别为 HTML 表格页 · 通道=raw`。

### 16.8 GitHub 目录批量

1. 填**仓库目录地址** → 点"列出文件"；
2. **多选**：默认勾选常见文档（**md / csv / tsv / txt / html / json**），并**显示每个文件的体积**；可"**全选 / 全不选 / 恢复默认**"；
3. 点抓取 → **逐个抓取（带进度条）** → **合并**。

- **限额**：**单文件 ≤ 2 MB、一次 ≤ 20 个文件、合计 ≤ 20 MB**；超出会明确拦下，你可以改选后再来。
- **个别文件失败**：会**逐个跳过并在状态行列出**，**不会整体中止**。
- **合并规则**：各文件**表头一致时自动合并成一张表**；**表头不一致时会提示"建议逐文件分别处理"**。

### 16.9 数据安全提醒

- 抓取过程**只在内存/临时文件里处理**，不写入你的主库；正式写入要经过 16.6 的"先保存、再导入（导入前自动快照）"这条路。
- 联网抓取的能力边界与已知限制，见 **12.14 / 12.15**。

## 20. 智能标签体系与批量自动打标（V2.1.0 新功能）

> 本章是 V2.1.0 新增。第 13 章讲的是"**怎么手动打标签、怎么看标签页面**"；本章讲 V2.1.0 新增的"**自动化**"部分：软件按一套"词表"给条目**自动打标签**，以及"词表""热点词"怎么维护。
> 本章全部功能**不联网、不上传**（唯一例外是你主动点"🔄 热点词更新…"去抓取自己填写的来源网址）。

### 20.1 什么是"智能标签"？内置库为什么一打开就有标签？

- **智能标签**：软件按一套**出厂词表**去"读"条目的文字与它所在的分类，自动判断该贴哪些标签。它是**纯本地规则匹配**（不调用大模型），所以结果**可预期、可复现、稳**。
- **出厂词表的构成（共 135 个标签）**：

| 组成 | 内容 | 标签数 |
|---|---|---|
| 通用骨架 | 所有条目共用，按"**领域 / 用途**"两个维度 | 18 |
| 领域维度包 | "**视觉**（54）/ **文学**（39）/ **编程**（24）"三个领域包，按"单主领域"装载 | 117 |
| 领域判定表 | 把"项目类别 / 根目录 / 一二级分类名"映射到某个领域（判定用，不计入 135 个标签） | —— |
| **合计** | | **135** |

- **打标的"三源优先级"**（先①、再②、最后③）：
  1. **显式标签**：来源文本里本来就带"**标签：…**"字样的，直接采用（最可信）；
  2. **分类名映射**：条目所在的项目类别 / 根目录 / 一二级分类名命中"领域判定表"→ 确定**主领域**；
  3. **领域包词典匹配**：确定主领域后，用该领域包的"匹配词"扫描条目文字打标签。
- **2026-09-15 推荐策略优化**：当条目**没有显式标签**时（即上面第①步没提取到"标签：…"），软件会**先**从「①名称 + ⑧中文提示词 + ⑨英文提示词」里直接切词取标签——
  - ①名称按"空白 + 标点"切（适合短语式标题，如 `AI绘画 赛博朋克` → `AI`、`绘画`、`赛博朋克`）；
  - ⑧⑨提示词只按"逗号 / 顿号 / 分号"切（适合列表式提示词，`film grain, portrait` → `film grain`、`portrait`，短语内部空格保留）；
  - 凑够 **3 个**即止；**不够 3 个时**，再由上面的「分类名映射 + 领域包词典匹配」补足。
  - 有显式标签时不受影响，仍按原三源优先级执行。
- **数量规则**：**单主领域**（一条只归一个领域）、**每个维度最多 1 个标签**、**每条条目合计 1~3 个标签**。
- **内置库已预置标签（阶段 1）**：出厂前已经用这套体系给内置整库打好了标签——**2555 条条目 → 622 个标签 / 6579 条标签关联**。于是：
  - **全新安装**（EXE 旁还没有 `data\prompts.db`）的用户，**打开标签页面就能直接看到大量现成标签**，并按标签浏览、筛选；
  - 预置时**不刷新条目的修改时间**，所以不会把全库条目都塞进当天的"变更包"。
- **老用户注意**：软件不会覆盖你已有的 `data\prompts.db`，所以你**不会自动得到这批预置标签**——请按 **20.2** 用「批量打标」给自己的数据就地补标签（也可参见 12.16）。

### 20.2 批量智能自动打标（V2.1.0 新增功能，重点）

**入口（两处，功能完全相同）**：
- 标签页面底部「**🤖 批量打标…**」（在"标签云 / 列表"档下）；
- 「⚙ 设置 → **标签与词表**」页 →「**🤖 批量智能打标…**」。

**① 选项说明（看好再点）**：

| 选项 | 可选值 | 说明 |
|---|---|---|
| 打标对象 | **仅无标签的条目**（默认）/ 全部条目 | 默认只给"还没标签"的条目补标签，**不会动你手工打的标签** |
| ② 范围 | **全部条目**（默认）/ 指定根目录（含子树）/ 当前列表 | 想只处理某一批条目时用 |
| ③ 数量上限 | **不限**（默认）/ 前 100 / 前 500 / 前 1000 | 避免一次处理太多；被截断的条目会在预演里明确列出 |
| ④ 每条例目标签数 | 1 / 2 / **3** | 与"合计 1~3 个"的规则一致 |
| ⑤ 标签重点范围 | 按维度勾选（**默认全选**） | 取消勾选即该维度不参与打分；「**领域**」与来源自带的「**显式标签**」**始终保留** |
| ⑥ 写入策略 | **追加（并入既有标签）**（默认）/ 覆盖（替换既有标签） | 一般保持默认；改成"覆盖"会替换该条目**原有**的标签，请谨慎 |

**② 操作步骤（务必按顺序来）**：

1. 打开入口，按下表选好选项；
2. 点「**🔍 预演（不写库）**」——这一步是**只读**的：会显示**范围内条目数、将处理多少条、因已有标签跳过多少条、因上限截断多少条**，并列出**逐条样例**（哪条会长出哪些标签）；
3. 看结果满意后再点**执行**。此时会弹**二次确认**，里面会如实告诉你：
   - 这次将处理多少条；
   - **执行前会自动备份数据库**（**备份失败就中止、一条也不写**）；
   - **这 N 条会被计入今日变更包**（因为打标会刷新条目的"修改时间"）；
   - 执行后可在「🕒 历史批次…」里**精确撤销**；
4. 确认后开始执行，底部状态栏显示处理结果；
5. 想反悔：点「**🕒 历史批次…**」→ 找到本次批次 → 点「**撤销**」，即可**只回退这一次打标**（把每条标签还原成打标前的样子，不影响你之后做的其它修改）。

**③ 三条"硬保障"（不用你操心，但值得知道）**：

| 保障 | 具体行为 |
|---|---|
| **必须先预演** | 没有预演结果不允许执行，杜绝"闭眼打标" |
| **执行前强制自动备份** | 写库前先生成打标前快照；**备份失败即中止**，不写入任何数据 |
| **批次可精确撤销** | 每次执行写一份"打标批次"明细到 `data\backup\tagging\打标批次_<时间戳>.json`（含每条"打标前 / 打标后"），**只保留最近 10 个**，可在「🕒 历史批次…」撤销 |

> 提醒：打标会刷新条目"修改时间"，被打标的条目会进入**当天变更包**——如果你正准备把变更包拷到另一台电脑，先想清楚这一点（弹窗里也会提示）。

### 20.3 词表管理（阶段 0.5）：词表可以自己改

**入口**：标签页面第 4 个页签「**词表**」；或「⚙ 设置 → **📚 词表管理…**」（两处是同一个界面）。

**三个按钮**：

| 按钮 | 作用 |
|---|---|
| 「**⬆ 导出词表…**」 | 把当前词表导出成 JSON（含 `universal` 通用骨架、`domains` 领域维度包、`domain_map` 领域判定表） |
| 「**⬇ 导入词表…**」 | 选一个 JSON 导入。软件**先校验结构**（不合法直接拒绝、**不写入**）；校验通过则**先自动备份当前词表**再导入（注意：是**整份替换**） |
| 「**↺ 恢复出厂词表**」 | 一键回到出厂的 135 个标签词表 |

**怎么新增一个"大类"（例如"学术"）——不用改代码：**

1. 点「⬆ 导出词表…」保存 JSON 文件；
2. 用记事本打开，在 `domains` 下**照着 `视觉 / 文学 / 编程` 的样子新增一个键**（如 `"学术"`），其下按维度写"标签名 → 匹配词列表"；
3. 如果还想让"看到某类分类名就归到学术"，可在 `domain_map` 里加上相应关键词映射；
4. 回软件点「⬇ 导入词表…」选中该 JSON → 通过校验即生效；
5. 之后打标时，主领域被判定为"学术"的条目就会用你新增的领域包打标；
6. 改坏了不要紧：点「↺ 恢复出厂词表」即可回到出厂状态。

> 关键点：**词表的权威数据存在数据库里**（meta 表的 `tag_dict` 键），所以在软件里改了就生效、也能随数据一起备份。

### 20.4 热点词表（阶段 4）

**是什么**：一张"**待匹配的热点词**"清单，用于辅助自动打标。它与"标签表"**完全隔离**——**热点词不会自动变成标签**。词条**初始为空**。

**入口**：标签页面「**🔥 热点词**」页签；或「⚙ 设置 → **🏷 热点词管理…**」。

**三种维护方式**：

1. **逐条添加**：在输入框里输入词条 → 添加；
2. **文本导入 / 粘贴**：支持导入 **txt / csv / md / json**，也可以直接把文本粘贴进去；
3. **从来源网址抓取**：点「**🔄 热点词更新…**」，填写**来源网址**（默认留空，需要你自己填），软件**先预览**抓到的词，确认后**并集追加**（已有的不会重复加）；**抓取失败不阻断**（只是这一次不追加）。

> 一句话区分：**热点词**是"给打标用的**候选词**"；**标签**是"已经**贴到条目上**的词"。

## 21. 设置对话框 4 页与性能优化（V2.1.0）

### 21.1 设置对话框按 4 页重排（V2.1.0）

原先 10 组设置平铺在一页，容易看花眼。V2.1.0 起改成 **4 个页签**：

| 页 | 里面放什么 |
|---|---|
| **界面** | "看得见"的设置：详情字段显示（自动 / 全部 / 精简）、在条目处显示标签、浮动提示开关、目录显隐等 |
| **数据与备份** | 电脑代号、自动备份保留份数、变更包保留天数、变更包携带被删快照等 |
| **标签与词表** | 三个管理入口：**📚 词表管理…**、**🏷 热点词管理…**、**🤖 批量智能打标…** |
| **关于** | 软件版本、**当前库数据统计**、开源仓库、联网说明，以及「**查看完整说明…**」按钮 |

> 功能与默认值都跟以前一致，只是**分门别类**更好找。

### 21.2 条目区"显示更多 / 全部显示"（V2.1.0 性能优化）

- **以前**：切到一个几千条的分类，会把每条都画出来 → 首屏慢、界面卡；
- **现在**：条目区**默认只渲染前 50 条**，顶部显示 **「已显示前 N 条 · 剩余 M 条（共 X 条）」**，并提供两个按钮：
  - 「**▼ 显示更多（+50）**」：每次再多显示 50 条（分步加载，推荐）；
  - 「**全部显示（共 X 条）**」：一次全显示；**超过 500 条时会先弹二次确认**，避免误点后长时间等待；
- **数据一条都没少**，只是"先画多少条"的差别；切换分类、搜索时会回到默认的前 50 条。

### 21.3 标签页面的"显示条数"（V2.1.0 性能优化）

标签区右上角「**显示**」下拉可选：**前 50（默认）/ 前 100 / 前 200 / 前 500 / 全部**。默认前 50 已能覆盖绝大多数使用场景；标签特别多时，按需放宽或直接选"全部"即可。

### 21.4 修复：标签云"标签一多只显示前几个"

V2.0.0 的标签云把所有标签按钮**横向平铺**，而界面框架**不会自动换行**，结果标签一多就只显示前几个（实测只显示 3 个）。**V2.1.0 已修复**：标签云改为**按标签实际文字宽度自动换行**，有多少显示多少（仍受 21.3 的"显示条数"上限控制）。

> 顺带说明为什么要限制显示条数：实测每条例目渲染约 **54ms**、每个标签列表行约 **68ms**、标签云每项约 **27ms**，而纯数据库查询只要约 **3ms**——**时间都花在"逐个画控件"上**。所以采用"先画一部分 + 需要时再加载"，让界面快速可用。
