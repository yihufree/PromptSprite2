## 1. 打包前准备

### 1.1 环境要求

| 项 | 要求 |
|---|---|
| 操作系统 | Windows 10 / 11（64 位）——**PyInstaller 不支持跨平台打包** |
| Python | **3.12**（3.10+ 理论可行，但本项目仅在 3.12 上验证） |
| 磁盘 | 至少 1 GB 可用（中间产物 + 产物） |
| 网络 | 首次打包需要（装 `pyinstaller`；之后可离线） |
| 权限 | 建议在普通用户下打包（不必管理员；管理员会改变产物所有权噪声） |

### 1.2 目录结构（与打包相关的部分）

```
PromptSprite/
├── app/
│   ├── main.py                       ← PyInstaller 的入口脚本
│   └── resources/
│       ├── builtin_manual.md         ← 内置手册（打进 resources/）
│       └── builtin_prompts.db        ← 内嵌完整库（由 build.py 生成，已 .gitignore）
├── Icons/
│   └── PSicon.png                    ← 托盘/窗口图标源（打进 Icons/）
├── build/
│   ├── PromptSprite.spec             ← 打包配置
│   ├── generate_icon.py              ← 由 PSicon.png 生成 app.ico
│   ├── app.ico                       ← 生成的 EXE 图标
│   └── build.bat                     ← 备选手工流程（不推荐用于正式发布）
├── data/prompts.db                   ← 开发态主库（打包时被复制为内嵌库）
├── dist/                             ← 产物目录（已 .gitignore）
├── build.py                          ← ★ 一键打包脚本
├── clean_builtin_meta.py             ← ★ 出厂库运行态 meta 清理/校验（硬门禁）
├── requirements.txt
└── run.py
```

### 1.3 依赖安装

```powershell
# 在项目根目录
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

`requirements.txt` 内容（**6 项，勿随意增删**）：

```
customtkinter>=5.2.0
Pillow>=10.0.0
pyperclip>=1.8.0
openpyxl>=3.1.0
keyboard>=0.13.5
pystray>=0.19.0
```

> `build.py` 会优先使用 `.venv\Scripts\python.exe`；若不存在则回退当前解释器。

### 1.4 内置库同步（自动，但要知道原理）

`build.py` 第 4 步会自动执行：

```
data/prompts.db  ──复制──▶  app/resources/builtin_prompts.db
```

- **作用**：让 EXE 内嵌"打包那一刻开发机上的最新数据"，用户首次运行就能看到完整内容；
- **若 `data/prompts.db` 不存在**：`build.py` 会打印提示"本次打包将不含完整数据库（仅内置手册）"，**但仍继续打包**；
- **重要**：`app/resources/builtin_prompts.db` 已在 `.gitignore` 中（避免把 8 MB 二进制提交进仓库）。

### 1.5 出厂库"运行态 meta"清理（**硬门禁，必须过**）

**为什么需要这一步**：内嵌库是从**开发机主库**复制的。而开发机运行软件时会把"运行态数据"写进 `meta` 表，例如：

- `incr_last_sync`（上次同步时间）
- `settings_window_size` / `settings_view_mode` / `settings_tag_view`（窗口大小、视图模式、标签页停留位置）
- **`settings_computer_code`（开发机的计算机名！）**

如果不清掉，**新用户首次安装会直接继承开发机的这些值**——体验差，且泄露开发机信息。

**`build.py` 第 4.5 步自动执行**（调用项目根的 `clean_builtin_meta.py`）：

| 子步 | 参数 | 作用 |
|---|---|---|
| ① | `--apply` | 删除白名单之外的 meta 键；**写前自动备份**到 `data/backup/` |
| ② | `--check` | 复核（退出码 0 = 已无运行态键） |

**白名单**（会被保留）：`schema_version` / `builtin_manual_version` / `tag_dict`。

> ⚠️ **2026-09-17 补充**：`schema_version` 的值现在应为 **`5`**（库结构 v5）。它是**必须保留**的键，**不是**运行态数据；若看到它是 `5`，属正常，不要清理。

**失败会怎样**：脚本缺失、调用异常、或任一子步退出码非 0 ⇒ **直接终止打包**（`sys.exit(1)`）。

> ⚠️ **这是发布质量的关键一环。** 若你手工绕过 `build.py` 用 PyInstaller 直打（见第 2.6 节），**必须自己先跑一遍** `python clean_builtin_meta.py --apply && python clean_builtin_meta.py --check`。

### 1.6 打包前回归测试（**必做，全绿才允许打包**）

```powershell
# ① 数据层统一自测（不开 GUI）
python -m app.self_test
#    → 期望：全部模块通过（数据库 / 备份 / 变更包 / MD 解析器 / 标签引擎 / 词表 / 打标批次 / 自动取词…）

# ② GUI 自动化回归（需桌面环境）
python -m app.gui_self_test
#    → 期望：ALL PASSED

# ③ GUI 冒烟（启动数秒后自动退出）
python -m app.main --smoke
#    → 期望：退出码 0
```

> 详细验收项见《项目需求规格和开发计划书 V10》第 8 章（**AC-01 ~ AC-31**；其中 **AC-29 ~ AC-31 为 2026-09-17 新增的 FR-93/FR-94 验收项**：修改语义、uuid 不随修改变化、多位置往返保真）。

## 2. 正式打包流程（唯一正规方式）

### 2.1 一条命令

```powershell
python build.py
```

### 2.2 `build.py` 的 7 个步骤（逐条说明）

| 步 | 打印 | 做什么 | 失败会怎样 |
|---|---|---|---|
| **1/7** | `pyinstaller 已安装` / `安装 pyinstaller ...` | 检测 `PyInstaller` 是否可导入；不可导入则 `pip install pyinstaller` | 安装失败 → 异常退出 |
| **2/7** | `安装/校验运行依赖（requirements.txt）...` | `pip install -r requirements.txt` | 失败 → `CalledProcessError` → 退出码非 0 |
| **3/7** | `生成应用图标 build/app.ico ...` | 执行 `build/generate_icon.py`（由 `Icons/PSicon.png` 生成 `build/app.ico`） | 失败 → 退出 |
| **4/7** | `准备内置完整数据库（打包进 EXE）...` | 复制 `data/prompts.db` → `app/resources/builtin_prompts.db` | 源文件不存在 → 提示后**继续** |
| **4.5/7** | `清理/校验内置库运行态 meta ...` | `clean_builtin_meta.py --apply` 然后 `--check` | 🔴 **任一失败 → 打印错误并 `sys.exit(1)`，终止打包** |
| **5/7** | `执行 PyInstaller 打包（onefile + windowed，含最新数据）...` | `python -m PyInstaller --noconfirm --clean build/PromptSprite.spec`（cwd = 项目根） | PyInstaller 非 0 → 退出码非 0 |
| **6/7** | `更新 EXE 旁数据文件夹 dist/data ...` | 复制 `data/prompts.db` → `dist/data/prompts.db`（**只更新 prompts.db，保留已有 images/backup**） | 源不存在 → 跳过 |
| **6.5** | — | 把 `dist/PromptSprite.exe` 重命名为 `dist/PromptSprite_<日期YYMMDD>_V<版本>.exe` | 未找到产物 → `sys.exit(1)` |
| **7/7** | `=== 打包完成：<路径>（xx.x MB）===` | 校验产物存在并打印体积 | 未找到 → `sys.exit(1)` |

> **注意**：`build.py` 用 `--clean` 执行，会清理 PyInstaller 的中间目录后重建（所以首次较慢属正常）。

### 2.3 打包耗时参考

| 阶段 | 大致耗时 |
|---|---|
| 依赖校验（已装齐） | 数秒 |
| 生成图标 | 1~3 秒 |
| 复制内置库（8 MB） | < 1 秒 |
| 出厂库 meta 清理 + 复核 | 1~3 秒 |
| **PyInstaller 打包（主要耗时）** | 数十秒 ~ 数分钟（取决于机器） |
| 重命名 + 校验 | < 1 秒 |

### 2.4 打包过程中的正常"噪声"

以下输出**不是错误**，可以忽略：

- PyInstaller 的 `WARNING: Hidden import ... not found`（本项目 `hiddenimports=[]`，此类警告多来自第三方库的可选依赖）；
- `INFO: Building COLLECT ...` / `Looking for ...` 等信息行；
- `upx` 相关提示（本项目 `upx=True`，若本机没装 UPX 会跳过压缩，不影响产物可用）。

### 2.5 打包后立刻要做的事

1. **核对产物名与体积**（见第 5 章自检清单）；
2. **实际双击运行一次**：确认能启动、首次能建库（可在一个空目录里测试）；
3. **记录 SHA256**（发布 Release 时贴出来，便于用户校验下载完整性）：

```powershell
# 把 <日期YYMMDD> 换成实际打包日期；当前 APP_VERSION 为 2.3.0（已发布过的示例：PromptSprite_260916_V2.1.0.exe）
Get-FileHash dist\PromptSprite_<日期YYMMDD>_V2.3.0.exe -Algorithm SHA256
```

### 2.6 备选：`build.bat` / 手工 PyInstaller（**仅用于快速验证，不建议用于正式发布**）

`build\build.bat` 与手工流程会**跳过** `clean_builtin_meta.py` 的硬门禁。如果非要用，**必须手工补齐**：

```powershell
# 0) 先保证内嵌库是最新的（缺一不可）
Copy-Item data\prompts.db app\resources\builtin_prompts.db -Force

# 0.5) ★ 出厂库运行态 meta 清理 + 复核（手工流程必须自己跑）
python clean_builtin_meta.py --apply
python clean_builtin_meta.py --check     # 退出码必须为 0

# 1) 生成图标（app.ico 已入库可跳过；改了 PSicon.png 才需重跑）
python build\generate_icon.py

# 2) PyInstaller 打包（在项目根目录执行）
python -m PyInstaller --noconfirm --clean build\PromptSprite.spec

# 3) 手工按命名规则改名（见第 4 章）
Rename-Item dist\PromptSprite.exe PromptSprite_<日期YYMMDD>_V2.3.0.exe
```

## 3. `PromptSprite.spec` 逐项核对

文件：`build/PromptSprite.spec`。**当前版本（V2.3.0）一行未改**（本轮为纯功能增强：未新增 `datas` / `hiddenimports`）。

| 配置项 | 值 | 说明 / 核对要点 |
|---|---|---|
| `Analysis([...])` 入口 | `app/main.py` | ✅ 与实际入口一致 |
| `pathex` | `[APP_ROOT]` | ✅ 项目根（`SPECPATH` 为 `build/`，其上级即项目根） |
| `binaries` | `[]` | ✅ 无额外二进制 |
| `datas` | ① `app/resources/builtin_manual.md` → `resources`<br>② `app/resources/builtin_prompts.db` → `resources`<br>③ `Icons/PSicon.png` → `Icons` | ⚠️ **三个资源缺一不可**：① 无手册 → 首次导入手册失败；② 无内嵌库 → 首次运行只有内含 90 条的手册数据；③ 无图标 → 托盘图标回退为程序绘制的绿方块 |
| `hiddenimports` | `[]` | ✅ 无隐式导入需求 |
| `excludes` | `matplotlib` / `numpy` / `pandas` / `scipy` / `IPython` / `jedi` | ✅ **体积关键**：显式排除这些大包（否则可能出现上百 MB 的产物） |
| `EXE name` | `PromptSprite` | 产物先产出 `PromptSprite.exe`，随后由 `build.py` 重命名 |
| `debug` | `False` | ✅ |
| `strip` | `False` | ✅ |
| `upx` | `True` | 若本机无 UPX 会自动跳过 |
| `console` | `False` | ✅ **windowed**：不弹黑色控制台窗口 |
| `icon` | `build/app.ico` | ✅ 由第 3 步生成 |
| `runtime_tmpdir` | `None` | ✅ |

**路径一致性要点**（易踩坑）：

- `config.resource_dir()` 打包态返回 `sys._MEIPASS`，因此 `datas` 的目标目录必须是 `resources/` 与 `Icons/`（**不带 `app/` 前缀**）；
- `config.builtin_manual_path()` 打包态 = `sys._MEIPASS/resources/builtin_manual.md`；
- `hotkey._icon_path()` 打包态 = `sys._MEIPASS/Icons/PSicon.png`。

## 4. 版本号与 EXE 命名规则

### 4.1 版本号唯一来源

**`app/config.py` 的 `APP_VERSION`** —— **唯一来源**，其他任何地方都不得硬编码版本号。

```python
# app/config.py
APP_VERSION = "2.3.0"
```

`build.py` 用正则从该文件读取：

```python
m = re.search(r'APP_VERSION\s*=\s*"([^"]+)"', ...)
```

### 4.2 命名规则

```
PromptSprite_<打包日期YYMMDD>_V<APP_VERSION>.exe
```

示例：

| 打包日期 | APP_VERSION | 产物名 |
|---|---|---|
| 2026-09-15 | 2.1.0 | `PromptSprite_260915_V2.1.0.exe` |
| 2026-09-16 | 2.1.0 | `PromptSprite_260916_V2.1.0.exe` |
| （**尚未打包**） | **2.3.0** | 打包后为 `PromptSprite_<日期YYMMDD>_V2.3.0.exe` |

> 日期取**打包当时**的系统日期（不是版本发布日期）。**同一天同版本二次打包会覆盖前一次的产物**（`build.py` 会先删同名旧文件再改名，避免被 PyInstaller 占用）。

### 4.3 是否需要升版本号？

| 情况 | 是否升版本 | 例 |
|---|---|---|
| 库结构（schema）变更 | ✅ 升 | V1.9.0 → V2.0.0（schema v4） |
| 导入导出格式变更 | ✅ 升 | 同上（JSON v5） |
| 重大功能新增 | ✅ 升 | V2.0.0 → V2.1.0（智能标签） |
| **库结构变更 + 格式变更（同时命中）** | ✅ **升** | **V2.1.0 → V2.2.0**（FR-93 条目稳定 ID schema v5 + JSON v6，2026-09-17） |
| 纯 UI / 文案 / 性能 / 兼容性修补 | ❌ **不升** | 09-15 / 09-16 两批增强 |
| **功能增量（导出范围确认 + 批量删除本分支 + 3 项修复 + 关于页精简）** | ✅ **升** | **V2.2.0 → V2.3.0**（2026-09-22；库结构仍 schema v5、格式仍 JSON v6、未新增第三方依赖） |

> ⚠️ **2026-09-22 起注意**：`APP_VERSION` 已为 `2.3.0`，因此**下次打包产物的文件名会自动变成 `..._V2.3.0.exe`**；若你只是想做一次"临时验证打包"，请记得改回或另存，避免与 V2.2.0 / V2.1.0 的正式产物混淆。

## 7. 常见打包问题 FAQ

### Q1：打包报错 `No module named PyInstaller`

`build.py` 第 1 步会自动安装；若因网络失败，手工装：

```powershell
python -m pip install pyinstaller
```

### Q2：产物体积异常大（> 40 MB）

**排查顺序**：
1. 检查 `build/PromptSprite.spec` 的 `excludes` 是否还在（`matplotlib` / `numpy` / `pandas` / `scipy` / `IPython` / `jedi`）；
2. 是否有新依赖被间接引入（`pip list` 对比 `requirements.txt`）；
3. `data/prompts.db` 是否是异常大的库（内嵌库会直接加进体积）；
4. `build/` 中间目录是否残留（`build.py` 已用 `--clean`，手工打包时需自己清理）。

### Q3：产物体积异常小（< 15 MB）

说明**内嵌库或手册没打进去**。检查：

```powershell
# ① 文件是否真的存在
Test-Path app\resources\builtin_prompts.db
Test-Path app\resources\builtin_manual.md
# ② distinct 的 datas 路径是否与 config 的读取路径一致（见第 3 章"路径一致性要点"）
```

### Q4：EXE 能启动但**首次运行报错 / 建库失败**

常见原因：
1. **`clean_builtin_meta.py --check` 没跑** → 出厂库带着开发机的 `settings_computer_code` 等运行态键（不会导致崩溃，但会误导用户）；
2. **EXE 放在只读目录**（如某些系统盘根目录、受保护的公司共享盘）→ `data/` 建不出来；
3. **杀毒软件拦截**了 EXE 首次运行时的文件操作 → 加白名单。

### Q5：双击 EXE **闪退、看不到任何信息**

`console=False` 所以看不到报错。**用源码跑一遍复现**：

```powershell
python app\main.py
```

这样能看到完整 traceback。

### Q6：托盘图标不显示 / 是"绿方块"

说明 `Icons/PSicon.png` **没打进包**（`datas` 的第 3 项）。此时 `hotkey.py` 会**回退为程序绘制的绿色方块 + P 字母**（不会崩，但不好看）。检查 spec 的 `datas` 第 3 项。

### Q7：全局热键 `Ctrl+Shift+P` 在打包版里失效

原因：`keyboard` 库需要**管理员权限**或**杀软白名单**才能装全局键盘钩子。
**不影响其它功能**（`main.py` 已做降级处理）。启动时会在状态栏提示。

### Q8：打包后 `dist\data\` 里的旧图片 / 备份被删了？

不会。`_update_dist_data()` **只覆盖 `prompts.db`**，保留已有的 `images/` 与 `backup/`。

### Q9：同一天打了两次包，第一个产物被覆盖了

正常。`build.py` 的产物名只含"打包日期 + 版本号"，同日同版本会**先删同名旧文件再改名**（避免被 PyInstaller 占用）。
**要区分多次打包**：改 `APP_VERSION`（如 `2.1.0` → `2.1.1`），或在发布时以 SHA256 区分。

### Q10：`PyInstaller` 报 `PermissionError` / 文件被占用

通常是**上一个 EXE 还在运行**（或托盘进程没退出）。彻底退出软件（含托盘 → 退出），必要时用任务管理器结束 `PromptSprite.exe`，然后重试。

### Q11：打包成功但用户在另一台机器上"数据是空的"

不是打包问题。是用户**把新 EXE 放到了新文件夹**，旁边没有旧 `data/`，于是软件新建了空库。
**在 Release Notes 里写明**："换文件夹时请把原来的 `data` 文件夹一起复制过去"。

### Q12：`clean_builtin_meta.py` 报错导致打包中止，怎么办？

```powershell
# 手工跑，看具体报什么
python clean_builtin_meta.py --apply
python clean_builtin_meta.py --check
```

常见原因：`data/prompts.db` 被占用（先关掉正在运行的软件）、`data/backup/` 不可写（检查权限）。
**不要为了"先打出来"而绕过这个门禁**——它拦的是"开发机隐私数据出厂"。

### Q13：能不能打成一个"绿色免安装压缩包"？

可以，就是 `dist\` 目录里 `PromptSprite_<日期>_V<版本>.exe` + `data\` 一起打包成 zip。目前 Release 采用**只发单个 EXE** 的方式（EXE 内已内嵌完整库，首次运行自动建 `data`）。

### Q14：macOS / Linux 能打包吗？

**不能**（当前仅 Windows 验证）。PyInstaller **不支持跨平台打包**；理论上在 macOS 上跑 `pyinstaller` 能出 Mac 产物，但本项目未做适配验证（`keyboard` / `pystray` / `winsound` 试听等均有平台依赖）。
